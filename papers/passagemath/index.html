Making passagemath more robust and easier to use

Davis Math Lab project report, Spring 2026

By Samuel Chen · Faculty mentor: Matthias Köppe

Jun 17, 2026

Read the PDF

Passagemath is a modular, pip-installable repackaging of SageMath. Rather than installing all of Sage, you install just the parts you need and run them in plain Python environments like Google Colab. That modularity is the source of a whole class of bugs: code written to assume a full SageMath install breaks when its optional dependencies are missing.

This report covers a quarter of work in Professor Köppe's undergraduate group. The contributions fall into three groups.

Fixing the modular-install bug pattern. A function tries to import an optional package, the import silently doesn't happen, and the function raises a NameError only when someone finally calls it. I fixed instances across combinatorics, number theory, and p-adics, and wrote check_unbound_imports.py, an abstract syntax tree scanner that finds the pattern across the whole codebase.

Build, CI, and plot rendering. Replaced the deprecated pkg_resources with importlib.metadata to fix Linux build crashes, and diagnosed a Windows CI failure caused by an invalid path format. Passagemath plots also used to appear in Colab and JupyterLite as the text Graphics object consisting of 1 graphics primitive instead of an image; adding _repr_png_ and _repr_svg_ to the Graphics class made them render.

Helping the team move faster. Onboarding and environment-setup docs, a list of shovel-ready issues with problem descriptions and suggested approaches, and guided exercise notebooks that hand a new contributor a real instance of the modular-install bug to fix. I also built pm-explore, which generates a runnable Jupyter notebook from any passagemath source file with the environment preconfigured — it reads the source as an AST, so it still works when the imports are broken.

The report closes on linear programming ergonomics, which I took up because using passagemath for MAT 168 meant writing nested loops and tracking indices by hand where cvxpy would not. Passagemath has a real advantage here: it does exact arithmetic over rationals and number fields, while cvxpy only handles floats. I documented how to retrieve dual values as a first step, then concluded that doing the rest properly needed more understanding of the backend than I had yet.
